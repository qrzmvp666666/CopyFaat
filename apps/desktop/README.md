# CopyFast Desktop

Run from the repository root:

```sh
pnpm desktop:dev
```

On macOS, development starts a locally signed `dist/dev/CopyFast.app`, using the CopyFast name, icon, application identifier and package version. The first launch prepares this bundle; subsequent launches reuse it. Main, preload, utility workers and native dependencies are copied into the same bundle so a separate build cannot replace workers under an older running main process; restart the development app to load main/worker changes. Grant accessibility access to this CopyFast app when prompted. Existing development task records are copied from the previous data directory only when the CopyFast data file does not exist.

The new-task dialog follows four steps: choose a platform, discover the current Discord source, map channels, and save collection rules. Discovery hides CopyFast and reads Discord accessibility information; success restores step three with the discovered server and channels. During discovery, the floating “退出识别” button or Escape pauses at the next safe desktop-operation boundary, shows the server and all observed channel names, and offers continue or exit. Continuing reactivates Discord and resumes; exiting returns the cached partial source/channel scope directly to step three. An exit before any observed channel returns to source guidance. Partial results retain real IDs where verified and local locators otherwise; the wizard labels incomplete coverage. Changing the source returns to discovery. There is no manual source/ID form or collector-file picker in the wizard. Telegram automatic discovery is not yet connected.

Step three shows source and destination cards above a source-channel → Webhook table. Users enter the target Discord channel's Webhook directly in each source row; there is no separate destination manager, add-channel step, global Webhook, or manual destination ID field. Several rows can use the same URL, but edits remain independent, including previously shared configurations. Search/select-all applies to visible sources, and temporarily unchecked rows retain their addresses. URLs are masked by default and only their format is validated. Existing single-URL records are migrated into individual channel addresses without replacing existing channel-specific URLs.

No real message is sent from the configuration screen. New tasks are saved paused and require a Discord Webhook for every selected source channel before they can run. Starting a task periodically checks the configured Discord channels: channels reported unread are opened and their currently accessibility-exposed messages are collected; channels reported read are skipped. Message IDs are deduplicated per task/channel, then local rules are applied and records are saved before delivery. Each saved message is posted to that source channel's Webhook. HTTP 429 responses are retried within the configured limit; ambiguous network/5xx outcomes are marked uncertain and are not automatically resent to avoid duplicates. A task can be paused at any point; already saved records remain available. The optional “采集并发送成功后，尝试滚动到最新消息” action is off by default and runs only after that channel's deliveries are terminal.

Collection is limited to the messages Discord exposes in its current accessibility tree; it does not fetch complete channel history. For actionable image/video/file nodes, the isolated collector obtains the original Discord CDN link from the attachment menu (without adding a source Bot). Before delivery, originals are downloaded into the private `media-cache` directory with source-message metadata and SHA-256 checksums, then uploaded together with text using multipart Webhooks. Confirmed delivery removes the cached files; rate limits, failures, and uncertain results preserve them. The current local limit is 10 attachments and 20 MiB total per message. Missing original links or oversized files stop that message with an explicit error instead of sending a partial text-only clone. A real macOS image has been verified through automatic link extraction, download, and a local multipart receiver; live video extraction and Windows still require separate samples/testing. Channels with no exposed messages can be recorded as empty. Discord may mark a channel read merely by opening it, independently of the optional scroll-to-bottom action. Webhook delivery is at-least-once only for explicit 429 retry responses; ambiguous outcomes require user review. Previously saved script-backed tasks retain their collector compatibility. Returning between steps preserves the draft and temporarily unchecked mappings. Escape closes the dialog and focus stays within it.

Each task currently selects one server/source and one or more channels. The workspace keeps task scopes separate and labels each channel group with its server/source name; the task name remains available on hover and in the task sidebar. Selecting a task opens its first channel; selecting a channel scopes both the message list and the collection log. The “全部频道” entry combines the current scope. Switching between messages and logs retains the selected channel. Task rules, pause/run, and deletion remain in the task header.

The task detail page aligns source and destination channels in one table. Rules default to a read-only summary; “编辑规则” opens the form, and “编辑对应” edits each destination name and masked Webhook independently. “仅保存，不运行” saves the full configuration and pauses the task; “保存并运行” saves paused first, then starts using the new rules. An active collection is cancelled and allowed to settle before a configuration change, preventing the previous round from overlapping a restart. Save failures retain the draft; start failures report that settings were saved but the task did not start. Live state updates do not reset edits, and navigation with unsaved changes asks before discarding them. Configuration alone does not prove delivery.

Future multi-source support should introduce stable source identity in task configuration, channel keys, collection cursors, messages, and logs before allowing a task to select multiple sources. Source display names must not be used as identifiers or used to merge channels across tasks. Discovered source/channel records may carry `identity` (`discord` or `local`) and a `locator` with server, category and channel names. A real ID is preferred from a channel URL or a verified current message-list element (`chat-messages-<channelId>-<messageId>`). Empty/unexposed channels keep explicitly labeled deterministic local keys, never AX refs. These keys are stable only while the server/category/channel names remain unchanged; renames require rediscovery. Custom collectors must honor these locators and return messages using the configured source channel keys. Discovery does not itself implement a history collector. New task configurations do not request a local collector; running them will become available when built-in collection is connected.

Discovery starts directly from the source step with no manual selection or confirmation overlay. On macOS the engine enables Discord’s supported renderer accessibility attribute, then waits through a three-second countdown before reading (maximum tree depth 50). After activating Discord, the engine reads the current window accessibility layout, resolves the unique Channels/频道 list, and confines scrolling to that sidebar within the pinned window. A non-focusable, mouse-transparent badge shows progress; Esc cancels and restores CopyFast with its draft. Missing or ambiguous sidebars stop the scan rather than scrolling the message pane.

Discovery runs in an isolated Electron utility process with bounded operations. It uses Koffi to load agent-desktop 1.3.1’s native FFI (ABI 7), not an installed CLI. Runtime lookup checks the bundled engine first and then the development output, so opening the development .app directly without environment variables also works. Build/dev downloads the platform release, checks its pinned SHA-256 and internal manifest, and packages the library with its required helper and Apache license/notice. electron-builder prepares each destination architecture before packing. This encapsulation is not encryption or a promise that dependency provenance cannot be identified. No cloud service, screenshot upload or account/subscription checks are involved. Observed channel names are retained before slower ID verification. If Discord leaves the foreground after channels are found, scanning stops and returns the observed channels as a partial result for review; explicit cancellation still returns to step two and preserves the previous draft, accessible via “查看已识别频道”. Raw AX snapshots/message bodies are not written into CopyFast’s task store or application logs; the native library manages its own temporary refmap state.

Window geometry is refreshed after activation and before each sidebar scroll, so transient activation bounds or moving the same window do not invalidate the scan. Incomplete AX snapshots receive up to four reads before an actionable failure. The scan verifies window/process identity, stops if the window/server changes, and refuses ambiguous same-category channel names. Stop-at-bottom is heuristic, so the result is always labeled for manual coverage review: hidden/inaccessible channels and virtualized unloaded areas cannot be guaranteed. Limit: 500 channels, 12-minute scan, 15-minute session. Windows bindings/build assets are wired but require testing on Windows; macOS library loading and ABI are checked separately from a successful live Discord scan.

The channel panel has a top-right expand/restore button. Expanding temporarily collapses the app sidebar and hides the page heading, demo banner, and metrics while retaining channel navigation and list state. Restoring returns to the previous sidebar preference.

Message lists support author/content search, time filtering, pagination and a detail dialog. Each channel log records its batch, discovered messages, saved messages and skipped messages. Empty completed rounds show “无新增”; interrupted rounds leave counts unconfirmed. Older task logs remain labeled as task batch totals. Deleting a task preserves its messages and channel history.

Failed rounds wait for the configured retry interval. After the retry allowance is exhausted, collection returns to its regular polling interval and continues automatically; invalid task configuration still requires attention. Completed, failed and cancelled collection workers are terminated before the next round. Pausing a task cancels pending retries. Channel results are stored locally alongside existing task data.

Verification commands:

```sh
pnpm desktop:test
pnpm desktop:type-check
pnpm desktop:build
```

To check the UI, create a task containing multiple channels, collect messages, then select each channel and switch between messages and logs. Verify that channel counts differ as expected, empty channels remain visible, and “查看本轮消息” opens a message from that channel and batch. These UI checks do not by themselves verify collection against a real desktop application.

The sidebar “联系客服” button reuses the SaaS Discord/Telegram monochrome icons and opens `/zh/contact` on `NEXT_PUBLIC_MARKETING_URL`. Without that environment variable it uses the current local marketing address, `http://copyfast.localhost:4101`. Configure the marketing origin in the desktop runtime environment when using another deployment.

In the discovery exit overlay, search by channel name or category and uncheck unwanted channels. All observed channels start selected; Select all and Clear apply to the entire list. Only checked channel IDs are returned to the mapping step, with verified identities and fallback locators preserved. Continuing discovery keeps the current exclusions in the overlay; newly discovered channels start selected. Clearing every channel returns to source settings without replacing the previous draft.

扫描进度：采集时在 Discord 当前可见频道行上显示透蓝色高亮，并在右下角展示频道名与扫描进度；已读频道显示已读跳过。高亮使用当前原生窗口坐标，不会点击或更改频道已读状态来展示进度；定位不唯一时不显示高亮。新采集日志按时间范围、去重、关键词及内容规则统计跳过原因；历史日志未保存原因时不会自动推断。

Task rule editing includes a collection start selector: preserve the existing timestamp (default), start now, last hour, or last 24 hours. New relative ranges are calculated when saving. These settings filter readable messages; they do not load complete history or reprocess already recorded message IDs.

### Image previews

Collected image attachments with HTTPS URLs appear as thumbnails in the message list and message details. Click a thumbnail to view the full image; close it with the close button or Escape. Multiple images use a grid. Expired links or network failures display an unavailable-image message. Older records containing only attachment labels cannot display an image until its URL has been collected. Previews currently load from the original URL and are not an offline archive.
